# 目的
Order ONEの集計アプリにおいて、CSV取り込み時の商品名変換ロジックを改修します。「お礼ID」をキーとしてマスタからデータを引き当て、元の「お礼品名」を破壊せずに、新しく「発注商品名」という列をフロントエンドのビューに追加して表示させることがゴールです。

# 前提条件
- 今後マスタの「お礼ID」の値が変更・追加されても、コードの改修なしに動的にマッチングできる設計にしてください。
- 参照するマスタファイルは `satohuru_masta.csv` と `sincho.csv` です。これ以外のファイル名は使用しないでください。

以下のTask 1からTask 4までを順番に実行し、各タスクが完了するごとに動作確認または報告を行ってください。

## Task 1: マスタ参照ロジックの厳格化 (`check_item.py`)
`check_item.py` の `get_normalized_name` 関数を改修してください。
- 処理対象が「さとふる」の場合は `satohuru_masta.csv` を、「新朝プレス」の場合は `sincho.csv` を参照するように分岐させてください。
- 文字列の部分一致などではなく、引数で受け取る「お礼ID（CSV側の値）」と、マスタ側の「お礼ID」の数値をキーにして完全一致で検索を行ってください。
- マッチした場合、マスタ側の「発注商品名」の値を返却するようにしてください。マッチしない場合は、一時的に元の商品名か空文字を返すように安全なフォールバックを実装してください。

## Task 2: インポート時のデータ保持と列追加 (`database.py`)
`database.py` のCSV取り込みロジック（`import_to_specific_table` 等）を改修してください。
- 取り込んだCSVの元データにある「お礼品名」の値は上書き・変換せず、そのまま「お礼品名」としてデータフレームに保持してください。
- 伝票発注番号等の処理で元の「お礼品名」が必要な場合は、この保持した値を参照するようにしてください。
- データフレームに新しく「発注商品名」という列を作成し、Task 1で改修した関数を利用して、マスタのIDと一致した発注商品名を自動的に格納してください。
- データベースのテーブル（`item1`など）のスキーマに「発注商品名」が正しく保存されることを確認してください。

## Task 3: フロントエンドのカラム定義の更新 (`constants/orderFieldConfigs.ts`)
フロントエンドで新しい列を認識できるように定義を更新してください。
- `SATOFURU_FIELDS` および `SHINCHO_FIELDS` の設定配列に、「お礼品名」をそのまま表示するフィールド定義と、新しく追加した「発注商品名」を表示するフィールド定義の両方が存在する状態にしてください。

## Task 4: ビューコンポーネントの描画更新 (`SatofuruDataView.tsx`, `ShinchoDataView.tsx`, `OrderTable.tsx`)
フロントエンドのテーブルビューでデータが正しく表示されるように改修してください。
- `OrderTable.tsx` のカラムマッピング処理を確認し、元の「お礼品名」と、マスタから取得した新しい「発注商品名」の列が独立してテーブル上に並んで表示されるように調整してください。
